Why a standard?

From document to executable research instrument

Codebooks are commonly distributed as PDFs, spreadsheets, or application-specific files. Their operational meaning must then be copied manually into annotation tools, prompts, and evaluation pipelines.

One definition, many implementations

Instructions, class boundaries, and examples remain connected to the codebook rather than being re-created separately for every model or tool.

Reproducible by construction

A codebook ID and version can be stored with each annotation, classification job, dataset, and published evaluation.

Compatible with manual coding

Conventional category codes, inclusion criteria, exclusion criteria, coding notes, and anchors have explicit representations.

A deliberately narrow scope

One CCA document defines one classification decision. It does not contain model settings, prompts, datasets, predictions, or an entire research project.

Core model

Four parts, one classification task

The mandatory core stays small. Optional detail makes complex codebooks precise without burdening simple tasks.

01

Identity

A stable ID, title, description, and semantic version.

02

Task

General instructions, coding unit, mode, and optional context.

03

Categories

Stable IDs, labels, definitions, criteria, notes, and aliases.

04

Examples

Texts with expected labels, context, and explanations.

Reference codebook

Three-class sentiment analysis

A complete single-label codebook with positive, neutral, and negative categories, including boundary rules and six reference examples.

Sentiment analysis

Version 1.0.0 · English · single label

Positive

The text expresses an overall favorable evaluation, approval, satisfaction, praise, hope, or other positive sentiment toward the focal subject.

  • The text explicitly praises, recommends, approves of, or expresses satisfaction with the focal subject.
  • Positive evaluation clearly outweighs any negative evaluation.

Neutral

The text expresses no discernible overall positive or negative evaluation, or positive and negative evaluations are balanced without either prevailing.

  • The text is factual, descriptive, procedural, or interrogative without evaluative sentiment.
  • Positive and negative evaluations are balanced and no overall position prevails.

Negative

The text expresses an overall unfavorable evaluation, disapproval, dissatisfaction, criticism, concern, or other negative sentiment toward the focal subject.

  • The text explicitly criticizes, rejects, condemns, or expresses dissatisfaction with the focal subject.
  • Negative evaluation clearly outweighs any positive evaluation.
positive

“The new version is not bad at all.”
The negated negative expression conveys a favorable evaluation.

neutral

“The committee met on Tuesday and published its report.”
The passage reports events without evaluating them.

neutral

“The report identifies both advantages and disadvantages without recommending either option.”
The passage describes a balanced assessment and communicates no prevailing evaluation.

negative

“The service is unreliable, frustrating, and not worth the price.”
Several explicit criticisms produce a clearly unfavorable overall evaluation.

negative

“Brilliant. It deleted all my work again.”
The positive word is used sarcastically; the complete passage and context convey dissatisfaction.

CCA Schema does not prescribe a prompt format. An application can deterministically construct one from the codebook:

You are performing the following classification task.

TASK
Three-class sentiment analysis

INSTRUCTIONS
Assign exactly one category representing the overall evaluative sentiment expressed by the author or speaker toward the focal subject. Base the decision on evaluative language in the unit of analysis. Do not infer sentiment solely from the topic's generally positive or negative connotations. Treat factual statements without a discernible evaluation as neutral. When both positive and negative evaluations occur, assign the sentiment that is clearly dominant; assign neutral when they are balanced and no overall evaluation prevails. Interpret negation, intensifiers, idioms, and clearly supported irony or sarcasm compositionally. Use supplied context only to resolve references or meanings in the text being classified.

UNIT OF ANALYSIS
A single text passage supplied for classification.

CATEGORIES
positive — Positive
Definition: The text expresses an overall favorable evaluation, approval, satisfaction, praise, hope, or other positive sentiment toward the focal subject.

neutral — Neutral
Definition: The text expresses no discernible overall positive or negative evaluation, or positive and negative evaluations are balanced without either prevailing.

negative — Negative
Definition: The text expresses an overall unfavorable evaluation, disapproval, dissatisfaction, criticism, concern, or other negative sentiment toward the focal subject.

Validate outside the browser

Use any Draft 2020-12 implementation for structural validation, then add two small integrity checks for category IDs and example references.

import json
from jsonschema import Draft202012Validator, FormatChecker

with open("cca-schema-0.1.schema.json", encoding="utf-8") as f:
    schema = json.load(f)
with open("codebook.cca.json", encoding="utf-8") as f:
    codebook = json.load(f)

validator = Draft202012Validator(schema, format_checker=FormatChecker())
errors = sorted(validator.iter_errors(codebook), key=lambda e: list(e.absolute_path))

for error in errors:
    path = "/" + "/".join(map(str, error.absolute_path))
    print(f"{path}: {error.message}")

if not errors:
    print("Structurally valid CCA codebook")
import Ajv2020 from "ajv/dist/2020.js";
import addFormats from "ajv-formats";

const ajv = new Ajv2020({ allErrors: true });
addFormats(ajv);

const validate = ajv.compile(schema);
const valid = validate(codebook);

if (!valid) console.table(validate.errors);
else console.log("Structurally valid CCA codebook");

Questions

Scope and interpretation

CCA Schema standardizes the representation of a coding instrument—not its empirical quality or the behavior of a particular classifier.

Why does one document describe only one task?

A single task is the smallest portable unit. It can be imported, evaluated, versioned, and reused without also importing unrelated variables from a large project codebook.

Why are category IDs strings?

Strings preserve leading zeros, permit semantic identifiers such as positive, and avoid treating manual codes as quantities. Numeric-looking IDs such as "102" remain valid.

Are examples required?

No. A zero-shot codebook can contain only instructions and category definitions. Examples add operational guidance and can be selected as few-shot demonstrations.

How are negative anchors represented?

An example labeled with category B is simultaneously a negative anchor for category A when it illustrates their boundary. Its explanation can make that contrast explicit.

Does CCA Schema define the LLM prompt?

No. Prompt construction, reasoning fields, confidence, model parameters, seeds, retries, and evaluation metrics belong to execution profiles or applications such as CCA-Lab.

Does a valid file define a valid measurement?

No. Technical conformance does not establish construct validity, category completeness, intercoder reliability, or classification accuracy.

Can it represent multi-label tasks?

Yes. Set classification_mode to multi_label; each example may then contain more than one category ID.

Can a codebook be multilingual?

Not in v0.1. Each document uses one language. Translations should be separate, versioned codebooks rather than language objects inside the same file.

Status and governance

An experimental standard, open to refinement

Version 0.1 establishes the slim core. The next step is testing it against diverse manual codebooks and independent software implementations.

Draft status

CCA Schema v0.1 is intended for experimentation and interoperability testing. Until governance, licensing, and a canonical repository are finalized, implementations should preserve the exact schema URI and codebook version they use.

Codebook versioning

  • PatchEditorial correction without intended semantic change
  • MinorNew examples or operational clarification
  • MajorCategories or rules change comparability
Methodological limitation

A CCA-conformant document is syntactically and internally consistent. Conformance does not establish the validity, reliability, fairness, or empirical performance of the classification task.
